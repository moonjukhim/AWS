1. 반려동물 AI 돌봄 플랫폼

코넬대 반려견 건강 상담 생성형 AI

AWS Public Sector Blog

Amazon Bedrock(Claude), Bedrock Knowledge Bases, EKS로 만든 RAG 상담 구조입니다. 코넬대 수의대 자료를 지식 기반으로 쓰고, 진단이 아닌 정보 제공용이라는 고지를 넣었으며, 교수진이 답변을 검토합니다.

참고할 부분: AI 상담 계층, 그리고 "진단은 수의사가" 맡는 경계 설정

Amazon Personalize 반려동물 추천 패턴

AWS Prescriptive Guidance

Kinesis로 이벤트를 받고, Lambda, Personalize, Step Functions로 실시간 추천, 재정렬, 주기적 재학습을 처리합니다. 반려동물 입양 사이트를 예로 들며, CDK 코드가 공개되어 있습니다.

참고할 부분: 개인화 추천 엔진. 재정렬 단계 뒤에 알러지·질환 금기 안전 필터를 추가하면 됩니다.

퓨리나 스마트 보울 IoT

AWS for Industries

AWS IoT Core로 스마트 보울 센서 데이터를 클라우드에 연결하고, 이 데이터를 분석해 맞춤 급식 추천과 알림을 제공합니다.

참고할 부분: IoT 기기 데이터 수집 계층. 이 글에서 쓴 IoT Analytics는 지원 종료 대상으로 알려져 있어, 지금은 Kinesis, S3, Timestream 등으로 대체해야 합니다.

2. 구급차 안의 기록 담당 AI

AWS HealthScribe + Amazon Q Business로 진료 대화 분석

AWS Machine Learning Blog

HealthScribe는 음성 인식과 의료 특화 생성형 AI로 예비 진료 기록을 자동 생성하는 HIPAA 적격 서비스입니다. 화자 역할 구분과 단어 단위 타임스탬프를 제공합니다.

참고할 부분: 음성을 기록으로 바꾸는 핵심 엔진. 구급대원과 환자의 발화를 구분하는 데 씁니다.

상호운용 가능한 임상 음성 애플리케이션 만들기

AWS for Industries

음성 기반 임상 앱이 만든 기록을 AWS HealthLake에 FHIR R4 형식으로 저장하는 방법을 보여줍니다.

참고할 부분: 구급차에서 만든 기록을 병원 응급실에 표준 형식으로 넘겨주는 구간

eVisit의 구급차 원격진료(ET3 프로그램)

AWS Public Sector Blog

구급대원이 AWS 기반 태블릿 앱으로 현장의 119 신고 환자와 응급의학과 의사를 원격진료로 연결하는 사례입니다.

참고할 부분: 구급차 현장 환경에서 AWS를 쓴 사례. 아키텍처 세부 내용은 적습니다.

3. 웨어러블 시계열 데이터 분석 및 생성형 AI 기반 개인 맞춤형 건강 행동 가이드 서비스

boAt 스마트워치 AI 코치

AWS Architecture Blog

스마트워치 앱 데이터를 Lambda가 받아 Bedrock(Llama 3.3)으로 개인 코칭 플랜을 생성합니다. 이력은 RDS와 DocumentDB에 저장하며, 수백만 사용자를 대상으로 6개월 넘게 운영 중입니다.

참고할 부분: 이 과제와 가장 가까운 서버리스 구조

Peloton IQ 개인화 인사이트

AWS for Industries

사용자 컨텍스트 데이터와 Bedrock의 LLM으로 주당 수백만 건의 개인화 인사이트를 생성합니다. 배치와 실시간 처리를 모두 지원합니다.

참고할 부분: 일일 가이드(배치)와 즉시 알림(실시간)을 나누는 설계, 프롬프트 엔지니어링

웨어러블 데이터 레이크

AWS for Industries

여러 제조사의 웨어러블 데이터를 데이터 레이크로 모으고, 조회하기 쉬운 형식으로 변환해 ML 모델 학습에 활용하는 방법을 다룹니다.

참고할 부분: 시계열 분석 앞단의 데이터 기반

4. 환자 중심 진료 연속성 · 기록 공유 · 지역 의료 이용 서비스

Well-Architected 헬스케어 렌즈: 상호운용성 참조 아키텍처

AWS 공식 문서

HL7 v2, v3, FHIR별 참조 아키텍처를 제공합니다. HealthLake가 비정형 데이터를 ICD-10-CM, SNOMED CT 같은 표준 용어와 연결하는 방법도 다룹니다.

참고할 부분: 기관 간 기록 공유의 표준 설계 기준

원격 환자 모니터링과 진료 연속성으로 건강 형평성 높이기

AWS for Industries

원격 환자 모니터링(RPM)과 진료 연속성을 함께 다루는 참조 구현 아키텍처입니다. 의료 취약 지역에 초점을 맞췄습니다.

참고할 부분: 진료 연속성과 지역 의료 이용 관점

DataArt의 HealthLake 기반 전국 단위 의료정보 교환

AWS Public Sector Blog

HealthLake 중심의 모듈형 구조로 정형·비정형 데이터를 FHIR R4로 변환합니다. 야간 배치 ETL을 거의 실시간 교환으로 바꿨습니다.

참고할 부분: 여러 기관이 기록을 공유하는 데이터 아키텍처

5. 진료한장: 말로 설명하면 병원 안내와 진료 요약지까지

Kyruus의 생성형 AI 의료진 매칭

AWS Machine Learning Blog

사용자가 증상과 위치를 자연어로 입력하면 Bedrock(Claude)이 이를 해석하고, OpenSearch로 적합한 전문의를 찾습니다.

참고할 부분: "말로 설명하면 병원 안내" 기능에 거의 그대로 해당

Clarus Care의 생성형 AI 음성 콜센터

AWS Machine Learning Blog

Amazon Connect, Lex, Bedrock으로 음성과 채팅을 처리합니다. Lambda가 긴급도와 의도를 분류하고, 필요한 정보를 추출하고, 응답을 생성합니다.

참고할 부분: 음성 입력 채널, 그리고 응급 상황을 따로 보내는 분기 설계

임상 기록에서 진단 코드 식별 가이던스

AWS Solutions Library

HealthScribe로 진료 대화를 요약하고, Comprehend Medical로 ICD-10-CM 코드를 붙이고, Bedrock으로 상태를 파악합니다. GitHub에 배포 코드가 있습니다.

참고할 부분: 진료 요약지 생성 구간
국내 적용 시 주의: AWS HealthScribe는 현재 미국 동부(버지니아 북부) 리전에서만 제공되어 데이터 보관 위치 요건이 걸릴 수 있습니다. 2번과 5번 과제를 국내에서 운영하려면 Amazon Transcribe와 Amazon Bedrock(서울 리전)을 조합하는 대안을 검토하세요. 출시 전에 최신 리전 지원 현황을 꼭 확인하세요.
