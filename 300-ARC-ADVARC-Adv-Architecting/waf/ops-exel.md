##### OPS 1. 우선순위를 어떻게 결정하나요?

- 공동의 비즈니스 목표를 바탕으로 무엇에 자원과 노력을 먼저 투입할지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 외부 고객의 요구 사항 평가 | 서비스를 이용하는 고객에게 무엇이 필요한지 파악합니다. |
| 내부 고객의 요구 사항 평가 | 사내 사용자와 관련 부서의 요구를 파악합니다. |
| 거버넌스 요구 사항 평가 | 조직의 정책, 책임, 의사결정 기준을 확인합니다. |
| 규정 준수 요구 사항 평가 | 준수해야 하는 법률·규제·계약·표준을 확인합니다. |
| 위협 환경 평가 | 서비스와 비즈니스에 영향을 줄 위협을 파악합니다. |
| 이점과 위험을 관리하며 절충 사항 평가 | 기대 효과와 위험을 비교하여 무엇을 우선할지 결정합니다. |

##### OPS 2. 비즈니스 성과를 지원하도록 조직을 어떻게 구성하나요?

- 누가 무엇을 소유하고 책임지며, 팀 사이의 역할을 어떻게 나누는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 리소스의 소유자 지정 | 시스템과 리소스마다 관리 책임자를 정합니다. |
| 프로세스와 절차의 소유자 지정 | 업무 절차를 유지·개선할 담당자를 정합니다. |
| 운영 활동의 수행 책임자 지정 | 배포·백업·장애 대응 등을 수행할 책임자를 정합니다. |
| 책임과 소유권을 관리하는 체계 마련 | 조직이나 업무가 변경되어도 담당과 책임이 명확하도록 관리합니다. |
| 추가·변경·예외를 요청하는 체계 마련 | 새로운 요구나 기존 정책의 예외를 요청하고 처리할 절차를 마련합니다. |
| 팀 간 책임을 사전에 정의하거나 협의 | 개발·운영·보안 등 팀 사이의 책임 범위를 합의합니다. |

##### OPS 3. 조직 문화는 비즈니스 성과를 어떻게 지원하나요?

- 구성원이 문제를 알리고, 필요한 조치를 취하고, 학습할 수 있는 환경인지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 경영진의 후원 확보 | 경영진이 목표 달성에 필요한 방향과 지원을 제공합니다. |
| 성과가 위험할 때 구성원이 조치할 권한 부여 | 문제가 예상되면 담당자가 필요한 행동을 취할 수 있게 합니다. |
| 에스컬레이션 장려 | 해결하기 어려운 문제를 상위 책임자나 전문팀에 적극적으로 알립니다. |
| 적시에 명확하고 실행 가능한 의사소통 수행 | 필요한 사람이 제때 이해하고 행동할 수 있도록 전달합니다. |
| 실험 장려 | 새로운 방법을 시험하고 결과에서 배울 수 있게 합니다. |
| 구성원의 역량 유지·성장 장려 | 교육과 학습으로 필요한 기술을 지속적으로 발전시킵니다. |
| 팀에 적절한 자원 제공 | 업무에 필요한 인력·시간·도구를 확보합니다. |


##### OPS 4. 워크로드에 관측성을 어떻게 구현하나요?

- 시스템의 상태와 동작을 이해할 수 있도록 필요한 데이터를 수집하는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 핵심 성과 지표(KPI) 식별 | 서비스가 목표를 달성하는지 판단할 지표를 정합니다. |
| 애플리케이션 텔레메트리 구현 | 애플리케이션의 메트릭·로그 등 상태 데이터를 수집합니다. |
| 사용자 경험 텔레메트리 구현 | 사용자가 경험하는 속도·오류·이용 흐름을 측정합니다. |
| 의존 대상의 텔레메트리 구현 | 외부 API·데이터베이스 등 의존하는 대상의 상태를 수집합니다. |
| 분산 추적 구현 | 요청이 여러 서비스를 거치는 경로와 처리 시간을 추적합니다. |


##### OPS 5. 결함을 줄이고, 수정을 쉽게 하며, 프로덕션 반영 흐름을 어떻게 개선하나요?

- 개발한 변경 사항을 품질 있게, 일관된 방식으로 운영 환경에 전달하는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 버전 관리 사용 | 코드와 설정의 변경 이력을 관리합니다. |
| 변경 사항 테스트 및 검증 | 변경이 의도대로 동작하는지 확인합니다. |
| 구성 관리 시스템 사용 | 환경과 설정을 일관되게 관리합니다. |
| 빌드 및 배포 관리 시스템 사용 | 빌드·배포를 표준 절차로 수행합니다. |
| 패치 관리 수행 | 보안 패치와 소프트웨어 업데이트를 관리합니다. |
| 설계 표준 공유 | 공통 설계 원칙을 팀이 함께 적용합니다. |
| 코드 품질 개선 활동 수행 | 코드 리뷰·정적 분석 등으로 품질을 높입니다. |
| 여러 환경 사용 | 개발·테스트·운영 환경을 구분합니다. |
| 작고 되돌릴 수 있는 변경을 자주 수행 | 변경 범위와 실패 영향을 줄입니다. |
| 통합 및 배포를 완전히 자동화 | 코드 통합부터 배포까지 자동화합니다. |


##### OPS 6. 배포 위험을 어떻게 줄이나요?

- 배포 실패에 대비하고, 문제가 생기면 빠르게 복구할 수 있는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 변경 실패에 대비한 계획 수립 | 배포가 실패했을 때의 복구 방법과 판단 기준을 정합니다. |
| 배포 테스트 수행 | 코드뿐 아니라 배포 절차 자체도 정상 동작하는지 검증합니다. |
| 안전한 배포 전략 사용 | 카나리·블루/그린 등으로 변경의 영향을 제한합니다. |
| 테스트와 롤백 자동화 | 문제를 자동으로 검증하고 필요하면 이전 상태로 되돌립니다. |


##### OPS 7. 워크로드를 지원할 준비가 되었는지 어떻게 확인하나요?

- 시스템뿐 아니라 담당 인력과 운영 절차까지 준비되어 있는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 담당 인력의 역량 확보 | 운영에 필요한 지식과 기술을 갖추도록 합니다. |
| 일관된 운영 준비 상태 검토 | 공통 체크리스트와 기준으로 운영 가능 여부를 점검합니다. |
| 런북을 사용하여 절차 수행 | 반복 작업을 정해진 단계에 따라 수행합니다. |
| 플레이북을 사용하여 문제 조사 | 장애 원인을 조사하고 대응 방향을 정하는 지침을 사용합니다. |
| 충분한 정보를 바탕으로 배포 결정 | 준비 상태와 위험을 검토해 배포 여부를 판단합니다. |
| 프로덕션 워크로드의 지원 계획 수립 | 지원 담당자·연락 체계·외부 지원 활용 계획 등을 마련합니다. |


##### OPS 8. 조직에서 워크로드의 관측성을 어떻게 활용하나요?

- 수집한 데이터를 실제 상태 파악과 문제 해결에 활용하는지 확인합니다. OPS 4가 수집 체계를 만드는 질문이라면, OPS 8은 그 데이터를 활용하는 질문입니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 워크로드 메트릭 분석 | 응답 시간·오류율·사용량 등의 수치로 상태를 파악합니다. |
| 워크로드 로그 분석 | 발생한 사건과 오류 기록에서 원인과 단서를 찾습니다. |
| 워크로드 추적 데이터 분석 | 요청 흐름을 분석하여 병목과 실패 지점을 찾습니다. |
| 실행 가능한 알림 생성 | 알림을 받으면 담당자가 필요한 조치를 취할 수 있도록 구성합니다. |
| 대시보드 생성 | 주요 상태와 지표를 한눈에 확인할 수 있게 합니다. |


##### OPS 9. 운영 활동이 정상적으로 이루어지는지 어떻게 파악하나요?

- 시스템 상태뿐 아니라 운영 업무 자체의 성과와 효율을 측정하는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 메트릭으로 운영 목표와 KPI 측정 | 복구 시간·배포 성공률 등으로 운영 성과를 측정합니다. |
| 운영 현황과 추세를 공유하여 가시성 확보 | 현재 상태와 변화 추세를 관련자들이 알 수 있게 합니다. |
| 운영 메트릭을 검토하고 개선 우선순위 결정 | 측정 결과를 바탕으로 먼저 개선할 업무를 정합니다. |


##### OPS 10. 워크로드와 운영 이벤트를 어떻게 관리하나요?

- 이벤트와 장애가 발생했을 때 서비스 영향을 줄이도록 대응 체계를 갖추었는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 이벤트·인시던트·문제 관리 프로세스 사용 | 상태 변화, 서비스 장애, 근본 원인을 체계적으로 관리합니다. |
| 알림별 대응 절차 마련 | 각 알림에 대해 담당자와 대응 방법을 정합니다. |
| 비즈니스 영향을 기준으로 운영 이벤트 우선순위 지정 | 고객과 비즈니스에 미치는 영향이 큰 문제부터 처리합니다. |
| 에스컬레이션 경로 정의 | 해결이 어렵거나 영향이 커질 때 누구에게 넘길지 정합니다. |
| 서비스 영향 이벤트에 대한 고객 소통 계획 수립 | 장애 시 고객에게 무엇을 언제 어떻게 알릴지 정합니다. |
| 대시보드로 상태 공유 | 장애 현황과 대응 상황을 관련자에게 보여 줍니다. |
| 이벤트 대응 자동화 | 정해진 조건에 따라 복구·알림 등의 작업을 자동 실행합니다. |

##### OPS 11. 운영을 어떻게 지속적으로 발전시키나요?

- 운영 경험에서 학습하고, 개선에 필요한 시간과 자원을 실제로 투입하는지 확인합니다.

| 선택 항목 | 이해하기 쉬운 설명 |
|---|---|
| 지속적인 개선 프로세스 마련 | 개선 사항을 발굴하고 실행·검증하는 절차를 운영합니다. |
| 인시던트 발생 후 분석 수행 | 장애의 원인과 대응 과정을 검토하여 재발을 줄입니다. |
| 피드백 순환 체계 구현 | 고객과 운영 현장의 의견이 개선 활동으로 이어지게 합니다. |
| 지식 관리 수행 | 운영 지식과 문서를 정리하고 쉽게 찾도록 관리합니다. |
| 개선을 추진하는 요인 정의 | 고객 요구·사업 목표·운영 문제 등 개선의 근거를 명확히 합니다. |
| 도출한 인사이트 검증 | 분석 결과와 개선 가설이 맞는지 데이터나 실험으로 확인합니다. |
| 운영 메트릭 검토 수행 | 운영 지표를 정기적으로 검토하여 성과와 문제를 파악합니다. |
| 교훈을 문서화하고 공유 | 성공과 실패에서 얻은 배움을 다른 구성원도 활용하게 합니다. |
| 개선을 위한 시간 확보 | 일상 업무와 별도로 개선 작업을 실행할 시간을 배정합니다. |
