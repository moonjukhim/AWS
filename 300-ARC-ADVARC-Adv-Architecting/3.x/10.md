## Large Scale Data Stores

1. **스토리지와 컴퓨팅을 분리합니다.** S3를 단일 정보 소스로 두고, Athena, EMR, Redshift, SageMaker 같은 엔진을 필요할 때 붙입니다. Hadoop처럼 스토리지와 컴퓨팅이 결합된 구조와의 핵심 차이입니다.
2. **비용 최적화는 데이터 기반으로 합니다.** 액세스 패턴을 예측할 수 있으면 스토리지 클래스 분석으로 수명 주기 정책을 만들고, 예측할 수 없으면 Intelligent-Tiering을 씁니다. 128KB 미만 객체와 30일 미만 보관 데이터는 Intelligent-Tiering에 맞지 않습니다.
3. **수십억 개 객체 작업은 직접 짠 스크립트가 아니라 인벤토리와 Batch Operations로 처리합니다.** 재시도, 진행 추적, 완료 보고서(감사 증적)가 기본으로 제공됩니다.
4. **권한 모델을 바꿉니다.** S3 버킷·객체 단위(IAM과 버킷 정책)에서 데이터 카탈로그의 DB, 테이블, 열 단위(Lake Formation 부여·취소)로 올라갑니다. 요청은 **IAM과 Lake Formation 검사를 모두 통과**해야 하고, 실제 데이터 접근은 임시 자격 증명으로 S3에 직접 이뤄집니다.
5. **데이터 레이크와 데이터 웨어하우스는 대체 관계가 아니라 보완 관계입니다.** 레이크는 읽기 시 스키마, 웨어하우스는 쓰기 시 스키마이며, 대부분의 조직은 둘 다 씁니다(레이크하우스 방향).
