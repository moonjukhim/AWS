### 1. 핵심 축: 운영 책임과 제어권의 스펙트럼

```text
 AWS가 더 많이 관리 ◀──────────────────────────────────────▶ 고객이 더 많이 제어

 Lambda │ ECS Express Mode │ ECS on Fargate │ ECS Managed Instances │ ECS on EC2
                           │ EKS Auto Mode  │ EKS + Fargate        │ EKS 관리형/자체 노드 │ EKS Hybrid Nodes / EKS-D
```

| 신규 옵션              |        시점 | 아키텍처적 의미 |
|-----------------------|------------|---|
| ECS Managed Instances | 2025년 9월  | EC2의 모든 기능(인스턴스 유형, GPU 등)을 쓰면서 프로비저닝·패치·스케일링은 AWS가 맡습니다. “Fargate는 제약이 많고 EC2는 운영이 무겁다”는 고전적 딜레마의 해법입니다. |
| ECS Express Mode | 2025년 11월 | 도메인, ALB(최대 25개 서비스 공유), 오토스케일링을 자동 구성합니다. App Runner는 2026년 4월 30일부터 신규 고객을 받지 않으며, AWS는 그 대안으로 Express Mode를 권장합니다. |
| EKS Auto Mode | 2024년 12월 | 컨트롤 플레인뿐 아니라 데이터 플레인(노드, 오토스케일링, LB, 스토리지, GPU)까지 AWS가 관리합니다. 슬라이드 51 |
| EKS Capabilities (Argo CD, ACK, kro) | re:Invent 2025 | GitOps와 AWS 리소스 관리를 AWS가 관리하는 플랫폼 계층으로 제공합니다. 플랫폼 엔지니어링 관점의 핵심입니다. |
| EKS Hybrid Nodes | 2024년 | 온프레미스·엣지 노드를 EKS 컨트롤 플레인에 연결합니다. 슬라이드 51의 하이브리드 시나리오를 갱신할 수 있습니다. |

### 2. 의사결정 프레임워크

| 기준         | ECS 쪽으로 기우는 신호 | EKS 쪽으로 기우는 신호 |
|-------------|---|---|
| 팀 역량·조직 | 작은 팀, AWS 중심, 플랫폼 팀 없음 | 이미 K8s 역량 보유(시나리오의 인수한 스타트업), 플랫폼 팀 존재 |
| 이식성 요구 | AWS 안에서만 운영 | 멀티클라우드·온프레미스 일관성, K8s API 표준 필요 |
| 생태계 | AWS 네이티브 통합(IAM, ALB, CloudWatch)으로 충분 | Helm, Operator, 서비스 메시, Karpenter, KEDA 등 CNCF 도구 필요 |
| 운영 부담 | 업그레이드 주기를 신경 쓰고 싶지 않음 | 연 3~4회 K8s 버전 업그레이드를 감당할 수 있음(Extended Support 비용 주의) |
| 워크로드 특성 | 웹·API·배치 위주 | ML/GPU 스케줄링, 복잡한 스테이트풀 워크로드, 멀티테넌트 플랫폼 |
| 비용 구조 | 컨트롤 플레인 요금 없음 | 클러스터당 컨트롤 플레인 요금, 대신 밀도 최적화 여지가 큼 |


##### 2-2. 컴퓨팅 선택 결정 트리 (예시)

```text
컨테이너가 꼭 필요한가? ── 아니오 → 이벤트 중심·짧은 실행이면 Lambda 검토
        │예
K8s API·생태계가 필요한가? ── 예 → EKS
        │아니오                    ├ 노드 관리를 맡기고 싶다 → EKS Auto Mode
        ▼                         ├ 격리 우선·소규모 → EKS + Fargate
       ECS                        └ 세밀한 제어·특수 하드웨어 → 관리형 노드 그룹 / Karpenter
        ├ 가장 빨리 웹/API 배포 → ECS Express Mode
        ├ 서버 관리 없이, 작업별 격리 → ECS on Fargate (+ Fargate Spot)
        ├ GPU·특정 인스턴스가 필요하지만 운영은 맡기고 싶다 → ECS Managed Instances
        └ 완전한 제어·최대 밀도·RI/SP 극대화 → ECS on EC2 (용량 공급자 + ASG)
```
