## 07. CI/CD

##### TO-DO

- **지속적 전달과 지속적 배포의 차이**는 시험과 실무 모두에서 자주 혼동됩니다. 핵심은 **수동 승인 게이트가 있느냐**입니다.
- **자동 롤백의 트리거는 두 가지**입니다. 배포 실패(후크 실패)와 **CloudWatch 경보**입니다. 경보를 연결하지 않으면 블루/그린의 장점이 반으로 줄어듭니다. 
- **블루/그린 비용**은 전환 기간 동안 두 배입니다. 컨테이너와 Lambda가 이 비용을 줄여주는 이유는 binpack과 사용량 과금입니다
- **StackSets는 Control Tower와 AFT의 기반 기술**입니다. 02 모듈에서 본 "새 계정이 OU에 들어오면 기준선이 자동 적용되는" 동작이 바로 서비스 관리형 StackSets의 자동 배포입니다.

##### SLSA(Supply-chain Levels for Software Artifacts) 프레임워크

SLSA 프레임워크: “소프트웨어를 안전하게 만들고 배포하려면 무엇을 확인하고 어떤 증거를 남겨야 하는가”를 정리한 공통 기준
특정 제품이 아니라, 조직이 개발·빌드·배포 과정을 설계하고 평가할 때 사용하는 기준

| 확인하고 싶은 질문 | 필요한 증거·통제 |
|-------------------------------------|---|
| 이 이미지는 어떤 코드로 만들었나요?      | 소스 저장소와 커밋 정보 |
| 누가, 어디에서 빌드했나요?              | 빌드를 수행한 플랫폼의 신원 |
| 어떤 과정으로 만들어졌나요? | 빌드 방식과 입력 정보 |
| 빌드 기록이 위조되지 않았나요? | 서명된 증명과 검증 |
| 다른 작업이 빌드에 개입할 수 있나요? | 격리되고 보호된 빌드 환경 |

- [Safeguarding artifact integrity across any software supply chain](https://slsa.dev/blog)
- [Well-architected best practices for software supply chain security](https://aws.amazon.com/blogs/security/well-architected-best-practices-for-software-supply-chain-security/)

##### AI 시대의 CI/CD

- AI 에이전트가 만든 변경도 같은 품질 게이트(테스트, 보안 스캔, 리뷰)를 통과해야 합니다.
- 테스트 생성, 코드 리뷰, 언어·프레임워크 업그레이드 같은 현대화 자동화에 AI를 쓰는 사례
- 에이전트에 부여하는 권한(리포지토리 쓰기, 파이프라인 실행)의 최소 권한 원칙
