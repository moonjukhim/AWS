## 2. 단일 및 다중 계정 

##### AWS Control Tower의 사용 사례

| 시나리오                     | 회사의 요구사항 예시 | Control Tower 활용 |
|----------------------------|---|---|
| **① 처음부터 AWS 환경 구축**      | “개발·운영·보안 계정을 분리하고 기본 관리 체계를 갖추고 싶다.” | 랜딩 존을 구축하고 계정 구조, 접근 관리, 로그·감사 기반을 구성 |
| **② 프로젝트별 계정 생성**        | “프로젝트가 생길 때마다 동일한 기준으로 계정을 만들어야 한다.” | **Account Factory**로 표준 계정 생성과 기본 설정 자동화 |
| **③ 기존 계정의 관리 체계 통합**  | “팀별로 사용하던 계정들을 중앙에서 관리하고 싶다.” | 기존 계정을 **등록(Enrollment)**해 Control Tower 관리 대상으로 편입 |
| **④ 조직별 보안 정책 적용** | “운영 환경에는 엄격한 통제를, 실험 환경에는 다른 기준을 적용하고 싶다.” | OU를 구분하고 각 OU에 필요한 **컨트롤(가드레일)** 적용 |
| **⑤ 로그·감사 체계 중앙화** | “여러 계정의 활동 기록과 보안 점검을 중앙에서 관리하고 싶다.” | 로그 아카이브·감사 계정을 기반으로 공통 관리 체계 구성 |
| **⑥ 정책 준수와 설정 변경 감시** | “계정이 늘어나도 표준 구성이 유지되는지 확인하고 싶다.” | 컨트롤 준수 상태와 **드리프트**를 확인하고 필요한 복구 수행 |
| **⑦ 계정 공급을 코드로 자동화** | “Terraform으로 계정을 요청하고 회사 공통 설정까지 배포하고 싶다.” | **AFT(Account Factory for Terraform)** 등으로 계정 생성·사용자 지정 자동화 | 


##### AF, AFC, CfCT를 통한 계정 생성

| 옵션                                   | 구성 방식 | 적합한 상황 |
|---------------------------------------|---|---|
| **기본 Account Factory**               | Control Tower 또는 Service Catalog 콘솔에서 계정 생성 | 계정 생성 빈도가 낮고, 기본 관리 구성이면 충분한 경우 |
| **Account Factory Customization(AFC)** | Account Factory에 **Service Catalog 블루프린트**를 연결해 계정 설정 자동 배포 | 별도 Git 파이프라인 구축 부담을 줄이면서 표준 설정을 적용하려는 경우 |
| **Customizations for AWS Control Tower(CfCT)** | **CloudFormation 템플릿과 SCP**를 파이프라인으로 배포 | 여러 계정·OU에 공통 리소스와 정책을 코드로 배포하려는 경우 |
| **API / CLI 기반 자체 자동화** | Service Catalog API 등을 Lambda·Step Functions·스크립트에서 호출 | 사내 계정 신청·승인 시스템과 연동하는 등 자체 절차가 필요한 경우 |
| **AFT** | Terraform과 Git 기반으로 계정 요청·설정 자동화 | Terraform을 표준으로 사용하고 계정 변경 이력을 Git에서 관리하려는 경우 |
